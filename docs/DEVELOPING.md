# 物品套装信息 / ItemSetInfo

版本 0.1.4，Windows x64，适配 Steam Build 25143593。

0.1.4 修正套装框显示一次后失效：原生附加框已经持有 UI 根节点，读取正文时不再错误地当作外层组件多取一层。访问前验证根节点的显示对象；游戏不提供有效节点时跳过尺寸调整，仍保留完整套装文本和原物品说明。

0.1.3 所有套装始终只用一个灰色卡片，内容很长时只增长此卡片自己的正文区域。固定原生图标组件到空白帧，不再播放眩晕/问号等无关图标。套装的完整效果与部件名单仍留在一个框中，标题和段落分别为“XX套装”“[效果]”“[套装部件]”。

在原版物品简介旁显示所属套装的信息：套装名称、触发件数与效果、完整部件名单。名单用【】标记当前查看的物品；同时属于多个套装的物品分别显示，无套装的物品不增加面板。

使用游戏自身的 `KeywordTooltip` 灰色卡片、字体与附加简介机制。默认排列在主简介右侧，与原有关键词说明一起排列；屏幕边缘的翻转、动画、离开隐藏和场景清理都交给原生系统。面板只显示资料，不接管鼠标或手柄输入。

目前接入库存物品框与回收物品框共用的物品简介入口，涵盖仓库、出击前库存以及其他场景打开的这类库存窗口。战斗中的主动技能说明走另一条路径，本版不改动它。

## 安装与停用

本体是 `mods/ItemSetInfo/ItemSetInfo.dll`，只需要已安装的 Mewjector API v3 加载器。运行、构建均不依赖 RoomCatList 或 FuckOffSteve。

运行 `apply-update.cmd`，会备份原文件、安装 `build/ItemSetInfo.dll`，并在游戏根目录 `chainloader.ini` 的 `[LoadOrder]` 末尾登记本 Mod。首次安装只新增文件和下次启动的加载项，可以在游戏运行时完成；更新已有 DLL 时须先退出游戏。保留现有 Mod 和根目录 `version.dll`；安装后校验 DLL 和配置。均由用户下次启动游戏时加载，不对运行中的游戏注入或热加载。

临时停用时，退出游戏后把整个 ItemSetInfo 文件夹移出 `mods`，放回原位置即可恢复。可以保留加载项；加载器会跳过不存在的 DLL。若手动清理加载项，应确保剩余的 `Mod1/Mod2/...` 编号连续。

不启动或关闭游戏，不读取、修改存档，不修改游戏 EXE/资源包，不覆盖 `swfs/ui.swf`、`swfs/house.swf` 或其他 Mod 的文件。效果属于界面显示，移除后不留下玩法改动。

## 构建与验证

需要 Visual Studio 2022 C++ Build Tools、Windows SDK 和 Python 3。运行 `build.cmd`，先校验受支持程序的哈希与 25 处原生代码/布局，再从本机资源生成套装资料、运行资料与加载配置测试，最后编译 DLL 并运行纯文本格式测试。

套装资料来自本机 `data/item_setbonuses.gon` 和物品定义；中文文案优先使用本机松散的 `data/text/combined.csv`，其余回退到资源包。名称、基础数值效果与说明一起解析，支持多套装关联。生成的游戏文字放在 `src/set_catalog.generated.hpp`，不纳入 Git，也不要单独再分发游戏资料。

运行时只在悬停物品改变时重建展示文字；每帧向原生提示系统提交，沿用其去重与生命周期。不保存原生物品或 UI 指针。遇到不支持的程序版本时拒绝安装挂钩，原版物品简介继续运行。日志写入共享 `mod_logs/chainloader.log`，前缀 `[ItemSetInfo]`。

`tests/panel_content_tests.cpp` 使用纯数据验证件数效果、紧凑名单、当前物品标记、未知物品及多套装关联；它不连接游戏、不调用原生接口。原生接口的调用约定、参数所有权和生命周期经过当前程序静态核对；游戏内显示效果由用户启动验证。

Mewjector 头文件来自本机已固定版本，保留 MIT 许可于 `licenses/Mewjector.txt`。其余功能独立编写。
